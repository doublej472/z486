# Divergences the lockstep still expects (run.py; README.md "Known divergences").

#   FINDING  PROGRAM  MODES  [counter=NAME]   # note
#
# MODES: step, pipe or step,pipe - the runs that must show it.  counter=NAME: the
# finding is judged on the harness counter NAME being nonzero (the harness tolerates
# and counts it everywhere else).  A run that diverges and is not listed fails the
# target; a listed one that no longer shows is reported GONE: remove its line with
# the fix.  B* are z486 bugs (numbers of the original lockstep evaluation), D* are
# documented implementation differences, H* harness limits.
#
# Fixed and no longer listed: B1 (dir/esc3, dir/esc4), B2 (dir/esc2, rand/g10, r224, g102,
# g114), B6 (pmd/b6*, rand/g25, g118),
# B15 (pmd/gdtlim_p58only, gdtlim_jmp, ldtlim, rand/g164, g301); B4 and B4a
# (pmd/retf_fault, iret_fault); B5 (dir/intr1); B9 (pmd/intlim3); B7 in protected mode
# (pmd/intlim2, intlim3); B4a-int (pmd/intlim); B7-DF (pm/pm8).
# B3's over-15-byte programs are listed as D-len15: 86Box has no length limit.

# B7: transfer to an EIP beyond the CS limit faults at the target (pushed IP = target).
# Fixed in protected mode; real and V86 mode keep the fetch-time #GP at the target
# (the i486 PRM states the transfer-time check only for protected mode)
B7   dir/xferlim    step,pipe

# B8: o32 PUSH Sreg straddling the 16-bit stack wrap: no #SS
B8   dir/stkwrap2   step,pipe

# D-errc16 (was B10): through a 32-bit gate the error code is a 2-byte write into its
# 4-byte stack slot, ESP still moving by 4; the slot's upper half keeps what the stack
# held, while 86Box writes 0.  This is what the Intel486 does: the Xe10's Am486DX4 leaves
# the upper half nonzero (PC-9821 core docs/probes/CPUSUITE-XE10-triage.TXT:
# callgate_newstack_ss data=55000038, ac_v86_iret data=00004400), the i486 PRM (1992)
# 9.8 Figure 9-6 labels bits 31-16 "UNDEFINED" and the text calls the upper half
# reserved; z486 adopted it in fork commit 3af3111 (test errcode_word_push).  The
# stepwise run tolerates it (errpad, synced into the model); the pipelined end state
# shows it in the handler's copy of the error code (only the upper half differs).  The
# gdtlim programs are B15's reproducers: their #GP is correct, its error code is this.
D-errc16  pmd/errcode            pipe
D-errc16  pmd/errcode32          pipe
D-errc16  pmd/errcode32b         pipe
D-errc16  pmd/gdtlim             pipe
D-errc16  pmd/gdtlim_b007        pipe
D-errc16  pmd/gdtlim_b007ss      pipe
D-errc16  pmd/gdtlim_ds          pipe
